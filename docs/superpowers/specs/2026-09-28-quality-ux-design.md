# castone_3 P5 — 검색 품질 · 동선 · UX/UI 설계

## 배경

P4까지 "일정 형태가 나온다"(성공률 1.00)는 달성했지만 실제 일정은 쓸 수 없다.
부산 2일 사례: 구간 이동 112분·113분, 저녁 21:02 시작. 측정 20건 평균 이동 240분/여행, 최대 834분.
기존 지표(지역 정확도·슬롯 충족·시간표 유무·환각)는 동선 현실성을 보지 않았다.

사용자 결정(2026-09-28):
- LLM 문장 품질(7B 한계)은 수용. 코드로 고칠 수 있는 검색·동선·UX만 다룬다.
- UI는 Streamlit 유지.
- 검색 방식 변경은 지표가 근거이므로 단계별로 측정한다(버그 수정은 건별 지표 없음 — 기존 결정 유지).

데이터 사실: 리뷰 청크 195,787개, 장소 16,134곳(장소당 리뷰 중앙값 10, 최대 225), 부산 청크 15,961개. 메타데이터에 좌표 없음.

## 1. 검색 품질

### 문제
| 문제 | 결과 |
|---|---|
| 전국 ANN top-50 후 지역 사후 필터 | 작은 지역은 후보 고갈, 동명 지역(경기 광주/광주광역시) 혼입 |
| 장소 점수 = 리뷰 청크 1개 유사도 | 우연히 쿼리와 닮은 한 줄 리뷰로 무명 장소가 상위 |
| 별점·리뷰 수 미사용 | 인기·검증 정도 반영 안 됨 |
| 취향 쿼리 결과 뒤에 기본 쿼리 결과를 단순 연결 | 두 쿼리 모두 상위인 장소가 불리할 수 있음 |
| 쿼리 = 지역명 + 추상 키워드 나열 | 리뷰 문장과 표현이 멀다 |

### 설계
- **지역 선필터:** 인덱스 로드 시 `지역 → 행 id 배열` 맵 생성. 검색은 `faiss.SearchParameters(sel=IDSelectorBatch)`(IndexFlat 지원)로 해당 지역 안에서만 수행.
- **장소 단위 집계:** 청크 결과를 (장소명, 지역)으로 묶고, 장소의 의미 점수 = 상위 3청크 유사도 평균.
- **RRF 융합** (`score = Σ 1/(60 + rank)`), 목록 3개:
  1. 취향 쿼리 의미 순위
  2. 기본 쿼리 의미 순위
  3. 인기 순위 — 베이지안 보정 별점 `(n·r + m·C)/(n + m)` (C = 전체 평균, m = 리뷰 수 중앙값) × log(1 + 리뷰 수)
- **쿼리 문장화:** 지역명 제거(필터가 담당), 리뷰 말투 템플릿 (`"{키워드} 좋은 {카테고리}"`).
- **보류:** BM25 하이브리드(kiwi 의존성 추가). RRF 결과 측정 후 부족하면 도입.

### 평가 — 실버 라벨 골든셋
- 쿼리: 지역 × 카테고리 × 구체 속성어(예: 해산물, 아이, 야경, 오션뷰, 조용한). 동의어 사전 포함.
- 정답: 해당 지역에서 리뷰에 속성어(동의어 포함)가 2회 이상 나온 장소. LLM 미사용, 메타데이터만.
- 지표: MRR@10, nDCG@10, Recall@20 + 기존 지역 정확도.
- 비교: ① 현재 ② 지역 선필터 ③ 선필터 + RRF.
- 한계 명시: 표현이 다른 적합 장소는 정답에서 누락되는 근사치 — 전후 비교용.

## 2. 동선

### 설계
- **좌표:** 후보의 상세 주소를 Google Geocoding으로 변환, 디스크 캐시(기존 Maps 캐시 재사용)로 장소당 1회. 여행 1건당 카테고리별 RRF 상위 약 15곳만.
- **하루 앵커:** 출발지(숙소) 입력이 있으면 매일 그 좌표에서 시작. 없으면 1일차는 관광지 1위, 이후 날은 전날 권역과 겹치지 않는 관광지 상위.
- **배정:** 슬롯 순서(점심→카페→관광→저녁) 유지. 각 슬롯에서 `RRF 점수 − λ·직전 장소 거리`가 최대인 후보. 직선 8km 초과 후보 제외, 후보가 없을 때만 해제.
- **재추천 금지:**
  - 같은 일정 내 중복 제외 (기존 유지).
  - 사용자가 뺀·교체한 장소는 `rejected` 목록으로 상태에 보관, 대안 후보·추가·교체 검색에서 제외.
  - 과거 여행 이력은 범위 밖(계정·저장소 없음).
- **이동 수단:** 입력에 자동차/대중교통 선택 추가. 경로 계산 모드에 반영.
- **도착·출발 시각:** 1일차 시작 시각, 마지막 날 종료 시각 입력(기본 12:00 / 18:00). 마지막 날 슬롯은 종료 시각까지 채운다(관광 1곳 고정 템플릿 폐기).

### 평가 — 동선 지표 (E2E 20건, 기존 평가 하네스에 추가)
- 구간 이동 시간 p50 / p95
- 60분 초과 구간 비율
- 저녁 시작 20시 초과 비율
- 여행당 총 이동 시간
- P4 결과(perf_after.json)가 전(before) 기준.

## 3. UX (정보 · 경험)

| 기대 | 구현 |
|---|---|
| 왜 여기인지 근거 | 카드에 별점, 리뷰 수, 매칭된 리뷰 한 줄 인용 |
| **리뷰 원문 보기** | 카드의 "리뷰 N개 보기" 펼침 — 해당 장소 전체 리뷰(로드 시 장소→리뷰 맵 생성), 취향 키워드 하이라이트 |
| 한눈에 보이는 동선 | Day별 지도(pydeck, Streamlit 내장) — 번호 핀 + 경로선 |
| 현실성 경고 | 60분 초과 구간·20시 이후 저녁에 경고 배지 |
| 쉬운 교체 | 슬롯마다 대안 2~3곳(같은 권역 RRF 차순위) 버튼 교체. 채팅 수정 유지 |
| 입력 반영 확인 | 결과 상단 칩: 동행 · 스타일 · 이동수단 · 추출 키워드 |
| 진행 상황 | `st.status`로 단계 표시: 지역 확인 → 장소 검색 → 동선 계산 → 설명 작성 |
| PDF | 이모지를 텍스트로 치환(🚶→도보, ➡→→). 지도 이미지 미포함 |

범위 밖(한계로 기록): 영업시간·휴무일(데이터 없음), 과거 여행 이력.

## 4. UI (Streamlit)

- `.streamlit/config.toml` 테마(색·폰트), 소량의 CSS.
- 입력 화면: 한 페이지 폼. 필수(목적지·날짜) 외 기본값. 이동수단·도착/출발 시각 추가.
- 결과 화면: Day 탭 → 좌측 카드형 타임라인, 우측 지도. 카드 사이 얇은 이동 줄(수단·시간·경고).
- 카드: 시간, 장소명, 카테고리 배지, 별점·리뷰 수, 인용, 리뷰 펼침, 교체 버튼.
- 새 의존성 없음. 구현 전에 목업으로 레이아웃 확인.

## 진행 순서
1. 검색: 실버 골든셋 → 현재 측정 → 선필터 → RRF (단계별 MRR/nDCG)
2. 동선: 좌표·앵커·배정·이동수단·시각 입력 + 동선 지표 전후 측정
3. UX 데이터: 장소→리뷰 맵, 대안 후보, rejected, 입력 칩, PDF 치환
4. UI: 목업 확인 → 테마·카드·지도·탭

## 에러 처리
기존 규칙 유지: 단계 실패는 `StepError`로 기록하고 서비스는 계속. 지오코딩 실패 장소는 거리 제약 없이 점수만으로 배정하고 경고 배지 표시.

## 테스트
순수 로직(RRF, 베이지안 별점, 지역 id 맵, 앵커 배정, rejected 제외, 이모지 치환)은 단위 테스트. 검색·동선은 평가 하네스로 전후 측정.
