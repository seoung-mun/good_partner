# P3 초안 생성 워크플로우 + 수정 에이전트 Implementation Plan

**Goal:** 초안 일정 생성을 LLM 루프(요청당 ~24회 호출, 성공률 45%)에서 결정적 LangGraph 워크플로우(LLM 2회)로 바꾸고, 사용자 수정은 얇은 tool을 쓰는 에이전트로 분리한다.

**Spec:** `docs/superpowers/specs/2026-09-28-castone3-refactor-design.md` 3장. 사용자 결정(2026-09-28): 건별 측정 없이 P3 완료 후 최종 평가 1회.

## 설계 결정 (스펙과 다른 점 포함)

| 결정 | 이유 |
|---|---|
| 목적지 지역 해석을 **결정적 코드**로 (`resolve_destination`), 모호할 때만 Maps | LLM 정규화가 '울산 동구'→'울산광역시'로 시군구를 잃고 '전북도' 같은 비표준명을 냄 |
| 슬롯별 `Send` 병렬 대신 **모든 슬롯 쿼리를 한 번에 배치 임베딩**하는 단일 검색 노드 | 서빙 대상이 CPU — 배치 1회가 스레드 병렬 N회보다 빠르고, torch·faiss 멀티스레드 충돌(세그폴트·MPS 교착)도 피함 |
| 검색 쿼리는 템플릿(`지역 + 카테고리`, `지역 + 취향키워드 + 카테고리`) | 멀티쿼리 LLM 호출 제거. 취향 키워드는 요청 파싱 1회에서 추출 |
| 장소 선택: 취향 쿼리 결과 우선, 슬롯 간 중복 배제 | 결정적·재현 가능 |
| 일정 내 순서는 템플릿 고정(점심→카페→관광→저녁) | 기존 규칙 유지. 경로 최적화는 수정 에이전트 tool로 |

## 태스크 (각각 TDD)

1. `resolve_destination`, `build_slots`, 모델 — 순수 로직
2. `search_slots` — 배치 임베딩 + `similarity_search_by_vector` + 지역·카테고리 필터 + 중복 배제
3. 체인 2개 — `with_structured_output`
4. 워크플로우 — parse → slots → search → assemble → routes ∥ weather → briefing
5. 평가 어댑터 — 출력 itinerary를 기존 지표 형식(`type/name/address/day`, `move`)으로
6. 수정 에이전트 — tool 4개 + `create_agent`
7. UI 연결 — `pages/trip_planner.py`가 새 워크플로우/에이전트 호출
